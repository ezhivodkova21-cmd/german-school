# Ежедневный сбор объявлений — Тюмень (вторичка + аренда)

Собирает объявления с четырёх площадок. Столбцы едины для всех:

```
Адрес, Площадь (м²), Тип, Цена (руб.), Цена за м² (руб.), Комнат, Этаж,
ЖК/Комплекс, Кто разместил, Объявлений у продавца, Дата публикации,
Ссылка, Источник, Дата сбора
```

## Яндекс.Недвижимость и Avito — `run_daily.py`

Работают через прямой HTTP-запрос (без браузера): на страницах поиска
обеих площадок объявления встроены в JSON прямо в HTML
(`window.INITIAL_STATE` у Яндекса, `data-mfe-state` у Avito).

```bash
python3 run_daily.py --out-dir ./output --owner-only
```

- Яндекс: поле `author.category` даёт тип продавца (Собственник/Агентство/
  Частный агент) прямо в списке — фильтр `--owner-only` работает сразу.
- Avito: тип продавца частично виден в списке — `item.iva.SecondLineStep`
  показывает текст "Агентство" для агентских объявлений, у частных
  обычно пусто. Это эвристика (не 100% надёжная — встречались единичные
  противоречивые случаи), но рабочая для практической фильтрации без
  захода на detail-страницы. `avito.py` заполняет поле "Кто разместил"
  этим значением (для частных — текст "Вероятно собственник...").
- Avito, продажа (`SALE_URL`): у "продажи вторичного жилья" на Avito НЕТ
  отдельного SEO-URL категории — рабочий путь только через полнотекстовый
  поиск `?q=продажа вторичной квартиры`. У этого URL сортировка по дате
  (`?s=104`) стабильно даёт 403 (проверено вживую) — поэтому для продажи
  объявления идут в порядке "по умолчанию" (НЕ хронологическом), и
  `--since-hours` работает только как пост-фильтр после сбора
  фиксированного числа страниц — часть свежих объявлений на большей
  глубине может быть пропущена. Для аренды (`RENT_URL`) сортировка по
  дате работает нормально.

**Ограничения по блокировкам:**
- Avito ограничивает частоту запросов (429) и может выдать полную
  блокировку по IP на несколько часов ("Доступ ограничен: проблема с
  IP", 403). Скрипт останавливается при такой ошибке, а не зависает.
- Если блокировка уже активна на момент запуска, `avito.py` вернёт
  пустой результат — это ожидаемо, попробовать снова позже.

## ЦИАН — требует ручной проверки перед автоматизацией

Рабочий URL: `https://tyumen.cian.ru/kupit-kvartiru-vtorichnyy-rynok/?is_by_homeowner=1`
для продажи, аналогично `snyat-kvartiru/?is_by_homeowner=1` для аренды.
Все нужные поля есть прямо в карточках списка (детальные страницы не
нужны).

ЦИАН защищён WAF (`waf-verdict: block, bot-detected`), который иногда
пропускает запросы, а иногда блокирует по IP на длительное время —
поведение непостоянное. Точную структуру HTML-карточек нужно
подтвердить в момент, когда доступ снова появится (селекторы не
захардкожены в этой директории, чтобы не закоммитить непроверенный
код).

## Юла — требует поиска через WebSearch, не чистый скрипт

Страница каталога Юлы — пустая SPA-заготовка без данных (JS
подгружает контент после рендера). Рабочий метод: найти ссылки на
конкретные объявления через WebSearch (`site:youla.ru ...`), затем
получить полные данные с каждой найденной страницы объявления — там
уже есть `window.__YOULA_STATE__` с `entities.products` (адрес, цена,
площадь, комнаты, этаж, статус "Собственник"/"Агент", количество
объявлений у продавца).

Это требует вызова инструмента поиска (WebSearch), недоступного из
обычного Python-скрипта/cron — поэтому Юла собирается только в
интерактивной сессии, не через `run_daily.py`.

**Важное ограничение для инкрементального сбора (последние часы/сутки):**
поисковые системы индексируют новые страницы объявлений не мгновенно —
проверено на практике: запрос за объявлениями "за последние 24 часа"
находит либо старые (проиндексированные месяцы/годы назад), либо не
находит вообще ничего нового. Метод пригоден для разового объёмного
сбора существующего рынка (так собирали изначальную базу), но НЕ
подходит для регулярного "лови новые объявления быстро" — для этого
нужен прямой доступ к каталогу Юлы (сейчас недоступен, см. выше) или
другой способ обнаружения свежих ссылок.
